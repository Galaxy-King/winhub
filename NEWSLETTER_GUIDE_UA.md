# Newsletter: інструкція користувача

Модуль `Newsletter` у WinHUB використовується для створення списків отримувачів і відправки поштових розсилок через налаштовані SMTP-профілі.

Розсилка може надсилатися у звичайному MIME-форматі або з GPG-шифруванням тіла листа та вкладень.

## 1. Доступ до модуля

Відкрийте WinHUB і перейдіть до модуля `Newsletter` через бокове меню або напряму за адресою:

```text
/module/newsletter
```

### Права доступу

| Дозвіл | Що дозволяє |
| --- | --- |
| `View` / `send_campaigns` | Відкрити модуль і відправляти розсилки |
| `Change` | Відправляти розсилки, керувати списками отримувачів і SMTP-профілями |
| `Delete` | Керувати списками отримувачів |
| Administrator | Повний доступ до всіх дій |

Якщо у вас немає потрібної кнопки, найімовірніше, обліковий запис не має відповідного дозволу.

## 2. Налаштування SMTP-профілю

SMTP-профіль визначає поштову адресу, з якої буде відправлятися розсилка.

### Як створити SMTP-профіль

1. Натисніть `SMTP Settings` у верхній панелі.
2. У блоці `Add New Profile` заповніть поля.
3. Натисніть `Save Profile`.

### Поля SMTP-профілю

| Поле в інтерфейсі | Що вказати |
| --- | --- |
| `Sender Email` | Email відправника, наприклад `news@example.com` |
| `SMTP Host` | Адреса SMTP-сервера, наприклад `mail.example.com` |
| `Port` | SMTP-порт, зазвичай `587` |
| `Password` | Пароль або app password для поштового акаунта |
| `GPG Keyserver URL` | Необов'язково; сервер для автоматичного пошуку GPG-ключів отримувачів |

Пароль SMTP зберігається у конфігураційному файлі в зашифрованому вигляді.

### Як видалити SMTP-профіль

1. Натисніть `SMTP Settings`.
2. У блоці `Saved Profiles` знайдіть потрібний профіль.
3. Натисніть кнопку видалення біля профілю.
4. Підтвердьте дію.

## 3. Створення списку отримувачів

Списки отримувачів використовуються як цільові групи для розсилки.

### Як створити список

1. У секції `Mailing Lists` натисніть `Create New`.
2. У полі `List Name` введіть назву списку.
3. У полі `Add Users` вставте отримувачів.
4. Натисніть `Add`.
5. Перевірте кількість у полі `Total Users`.
6. Натисніть `Save List`.

### Формат отримувачів

Отримувачів можна вводити:

- через кому;
- через пробіл;
- з нового рядка;
- як повний email, наприклад `user@example.com`;
- як коротке ім'я без домену, наприклад `user`.

Якщо отримувач не містить `@`, система автоматично додасть домен за замовчуванням. Типове значення:

```ini
NEWSLETTER_RECIPIENT_DOMAIN=@syneforge.com
```

Адміністратор може змінити домен у змінних середовища:

```ini
NEWSLETTER_RECIPIENT_DOMAIN=@example.com
```

### Як редагувати список

1. У секції `Mailing Lists` натисніть кнопку редагування біля потрібного списку.
2. Додайте або видаліть отримувачів.
3. За потреби скористайтесь полем `Search users`.
4. Натисніть `Save List`.

### Як видалити список

1. У секції `Mailing Lists` натисніть кнопку видалення біля списку.
2. Підтвердьте видалення.

## 4. Підготовка розсилки

Основна форма знаходиться у секції `Newsletter Setup`.

### Обов'язкові поля

| Поле в інтерфейсі | Що зробити |
| --- | --- |
| `Sender Profile` | Виберіть SMTP-профіль відправника |
| `Target Lists` | Виберіть один або кілька списків отримувачів |
| `Subject` | Введіть тему листа |
| `Email Body` | Напишіть текст листа |

### GPG Encryption

Перемикач `GPG Encryption` увімкнений за замовчуванням. У цьому режимі система шифрує лист окремо для кожного отримувача.

Якщо вимкнути `GPG Encryption`, система покаже додаткове підтвердження, тому що тіло листа буде надіслано відкритим текстом.

### Редактор листа

У полі `Email Body` доступне базове форматування:

- вибір шрифту;
- розмір тексту;
- жирний текст;
- курсив;
- підкреслення;
- марковані та нумеровані списки;
- вирівнювання;
- колір тексту;
- посилання;
- очищення форматування.

Чернетка автоматично зберігається у браузері. Якщо сторінку випадково оновити, введені дані можуть відновитися з локального сховища браузера.

## 5. Вкладення

Файли додаються через поле `Attachments`.

### Ліміти за замовчуванням

| Ліміт | Значення |
| --- | --- |
| Максимальна кількість файлів | `8` |
| Максимальний розмір одного файлу | `10 MB` |
| Максимальний сумарний розмір | `25 MB` |

Якщо `GPG Encryption` увімкнено, шифрується весь MIME-лист разом із вкладеннями.

Адміністратор може змінити ліміти через змінні середовища:

```ini
NEWSLETTER_MAX_ATTACHMENTS=8
NEWSLETTER_MAX_ATTACHMENT_BYTES=10485760
NEWSLETTER_MAX_TOTAL_ATTACHMENT_BYTES=26214400
```

## 6. Як працює GPG-шифрування

Коли `GPG Encryption` увімкнено, система виконує такі кроки:

1. Перевіряє, чи доступний GPG на сервері.
2. Перевіряє публічний ключ для кожного отримувача.
3. Якщо у SMTP-профілі вказано `GPG Keyserver URL`, пробує завантажити відсутній ключ.
4. Шифрує MIME-повідомлення для конкретного отримувача.
5. Надсилає зашифрований лист через SMTP.

Якщо публічний ключ отримувача відсутній, прострочений, відкликаний або непридатний, лист цьому отримувачу не буде надіслано. Розсилка завершиться зі статусом попередження.

Для роботи GPG адміністратор має налаштувати шлях до виконуваного файлу:

```ini
GPG_PATH=gpg
```

## 7. Відправка розсилки

Перед відправкою перевірте:

- вибрано правильний `Sender Profile`;
- вибрано потрібні `Target Lists`;
- заповнено `Subject`;
- заповнено `Email Body`;
- вкладення не перевищують ліміти;
- режим `GPG Encryption` відповідає вимогам розсилки.

Щоб запустити відправку, натисніть `Send Newsletter`.

Після натискання розсилка запускається у фоновому процесі. Кнопка відправки тимчасово блокується, а форма очищується після старту. Якщо потрібно бачити процес відправки в реальному часі, не закривайте сторінку одразу.

## 8. Перегляд логів

Натисніть `Logs` у верхній панелі, щоб відкрити вікно `Newsletter Sending Logs`.

У логах відображається:

- старт розсилки;
- підключення до поштового сервера;
- стан GPG-шифрування;
- прогрес відправки;
- підсумок виконання;
- помилки, якщо вони виникли.

Кнопка `CLEAR` очищає лише поточне вікно логів у браузері. Серверні логи завдань зберігаються окремо у директорії логів WinHUB.

Для звичайних користувачів частина технічних деталей приховується. Адміністратор бачить детальніші записи, зокрема кількість отримувачів і причини збоїв.

## 9. Історія та аудит

Кожна розсилка створює фонове завдання з модулем `Newsletter`.

В аудит записуються:

- старт розсилки;
- відправник;
- вибрані списки;
- кількість отримувачів;
- використання GPG;
- кількість вкладень;
- результат виконання зі статусом `Success`, `Warning` або `Error`.

Історію можна переглядати через модуль аудиту, якщо користувач має відповідні права.

## 10. Типові проблеми

### `No profiles configured`

SMTP-профілі ще не створені або у вас немає доступу до їх перегляду. Зверніться до адміністратора.

### `No lists created yet`

Немає списків отримувачів. Створіть список або попросіть адміністратора надати доступ до керування списками.

### `Please select at least one target list`

Перед відправкою потрібно вибрати хоча б один список отримувачів.

### `Please write an email body`

Тіло листа порожнє. Додайте текст у полі `Email Body`.

### `Sender profile not found`

Вибраний SMTP-профіль був видалений або сторінка має застарілу конфігурацію. Оновіть сторінку і виберіть профіль знову.

### `Mail server connection failed`

Перевірте SMTP host, port, пароль, доступність сервера та дозвіл на SMTP-auth для поштового акаунта.

### `GPG is unavailable`

На сервері не знайдено GPG або неправильно задано `GPG_PATH`.

### `Missing/Invalid GPG Key`

Для одного або кількох отримувачів немає придатного публічного GPG-ключа. Імпортуйте ключ вручну або налаштуйте `GPG Keyserver URL` у SMTP-профілі.

### `Attachment size limit exceeded`

Зменште кількість або розмір вкладень.

## 11. Рекомендований робочий процес

1. Адміністратор створює SMTP-профіль.
2. За потреби адміністратор додає `GPG Keyserver URL`.
3. Адміністратор або користувач із правом керування списками створює `Mailing Lists`.
4. Оператор вибирає `Sender Profile`, `Target Lists`, режим `GPG Encryption`, тему, текст і вкладення.
5. Оператор натискає `Send Newsletter`.
6. Оператор перевіряє `Newsletter Sending Logs`.
7. Адміністратор за потреби переглядає аудит і серверні логи.
