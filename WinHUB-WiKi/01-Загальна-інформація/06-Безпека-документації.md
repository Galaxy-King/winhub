# Безпека документації

Публікація WiKi не повинна змінювати конфігурацію сервера або створювати новий канал витоку секретів.

## Заборонено публікувати

- `SECRET_KEY`, `AGENT_API_KEY`, `AGENT_TASK_HMAC_SECRET`;
- `POSTGRES_PASSWORD`, SMTP/IMAP/LDAP/FreeIPA passwords;
- admin password і TOTP seed;
- приватні TLS та GPG-ключі;
- `master_key.enc`, `sys_secret.enc` та recovery bundle;
- реальні agent tokens, identity keys і bootstrap configs;
- внутрішні IP, hostname, email або назви груп, якщо простір Confluence не має відповідного рівня доступу;
- необроблені логи, звіти або screenshots із sensitive data.

## Як оформлювати приклади

Використовуйте позначки:

```text
<WINHUB_SERVER>
<AGENT_PUBLIC_PORT>
<CERTIFICATE_SHA256>
<SECRET_FROM_PASSWORD_MANAGER>
```

Не використовуйте навіть старі або відкликані production-секрети: вони можуть розкрити структуру внутрішніх систем або бути повторно використаними.

## Команди у WiKi

- Не додавайте команди, які послаблюють TLS, firewall або file permissions.
- `IgnoreTlsCertificateErrors=true` дозволено згадувати лише як заборонений production-параметр.
- Небезпечні операції видалення повинні мати чітке попередження й точний шлях.
- Перед публікацією перевіряйте, що приклади не містять shell history із секретами.

## Зберігання секретів

Recovery bundle нового сервера зберігайте за межами Confluence: у password manager або зашифрованому offline/off-host сховищі з обмеженим доступом і журналюванням.
