# Архітектура WinHUB

## Потік запиту

```text
Browser / Agent
      |
    HTTPS
      |
    Nginx :443
      |
      +-- Web/API backend 127.0.0.1:8443
      |        |
      |        +-- PostgreSQL
      |        +-- /var/lib/winhub
      |        +-- Report Renderer socket
      |
      +-- optional agent-only public port
```

Nginx завершує TLS і передає запити локальному backend. Backend не повинен бути доступним напряму з мережі.

## Серверні компоненти

- `server_debian.py` — production entry point;
- `core/agent_gateway.py` — enrollment, poll, telemetry та result;
- `core/database.py` — моделі даних;
- `core/security.py` — системне й payload-шифрування;
- `core/admin.py` — користувачі, API keys, аудит і GPG;
- `modules/Infrastructure` — Endpoint Management;
- `modules/HistoryAudit` — історія задач;
- `modules/Newsletter` — розсилки;
- `winhub-renderer.socket` — ізольований рендеринг звітів.

## Життєвий цикл агента

1. Агент виконує enrollment із bootstrap secret.
2. Сервер створює endpoint у стані `Pending`.
3. Адміністратор перевіряє й підтверджує endpoint.
4. Агент періодично виконує signed poll.
5. Сервер повертає підписану задачу або scheduling hint.
6. Агент виконує дозволену дію й повертає результат.
7. Сервер зберігає історію, telemetry, metrics і звіти.
