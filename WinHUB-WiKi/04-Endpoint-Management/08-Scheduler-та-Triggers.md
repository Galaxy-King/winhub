# Scheduler і Triggers

## Scheduler

Scheduler запускає затверджений template на endpoint/group за розкладом.

Перед збереженням перевірте timezone, target group, overlap, timeout, expected load і report delivery. `Run now` використовуйте як контрольний тест.

У налаштуваннях обов’язково заповніть причину запуску (`launch_reason`, до 2000 символів). Автоматичні запуски копіюють цю причину в кожну задачу. Для ручного `Run now` потрібно ввести окрему причину; вона не перезаписує причину збереженого розкладу.

## Triggers

Trigger rule порівнює metric із threshold та запускає action template.

Причина автоматичного запуску задається в налаштуваннях правила й копіюється в створену задачу. Текст метрики не використовується як причина.

Перевірте:

- точну назву metric;
- operator і type значення;
- hysteresis/cooldown логіку шаблону;
- target group;
- ризик повторних запусків;
- права template action.

Не використовуйте trigger для необмеженої remote shell action. Для destructive remediation потрібні додаткові guards і test rollout.

## Після оновлення з попередньої версії

Міграція `20260904_02` додає поля без зміни історичних записів. **Старі розклади та тригери без причини не відправлятимуть задачі.** У списку видно `Blocked: add a launch reason via Edit`; відкрийте кожну потрібну автоматизацію через `Edit`, заповніть причину й збережіть. Перевірте дату одноразового запуску, якщо вона вже минула. Пропущені запуски не надсилаються автоматично заднім числом.
