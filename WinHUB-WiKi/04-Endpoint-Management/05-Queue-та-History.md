# Queue та History

`Queue` показує поточні й завершені задачі, їхній endpoint, status, timestamps та terminal log.

У деталях групового запуску, окремої задачі та в `Audit & History` видно причину запуску. Збережена причина є знімком на момент створення задачі: редагування розкладу/тригера не змінює минулі записи. `Retry failed` запитує нову причину й створює новий запуск, зберігаючи стару історію.

Для історичних задач без цього поля відображається `Not recorded` — система не вигадує причини заднім числом. Скасування, перегляд і формування звіту не запускають новий код на хості та не потребують нової причини.

## Основні дії

- відкрити task details;
- переглянути terminal log;
- cancel pending tasks;
- retry failed job;
- finalize aggregated report;
- очистити завершену history відповідно до retention policy.

## Стани

Типовий шлях: `Pending → Running → Completed/Failed`. Cancel діє лише до або під час підтримуваної стадії.

`Audit & History` використовуйте для ретроспективного пошуку. Cleanup є destructive action: перед видаленням перевірте audit/legal retention requirements.

Task logs можуть містити sensitive operational data. Не копіюйте їх до WiKi без redaction.


## Панель Execution Queue

Лічильник Total та фільтр статусу Scheduled прибрані. Джерело запуску обирається окремо: All Tasks, Manual, Auto (Scheduler), Auto-Fix (Trigger). Статуси фільтрують результат: All Status, Pending, Success, Error, Cancelled. Заплановані rollout-записи можуть зберігати власний статус, але окремої кнопки Scheduled немає.

Квадратна кнопка Refresh у правому куті оновлює чергу та період історії; стрілка обертається під час запиту. Available task history показує найстарішу й найновішу дату та кількість дозволених task records. Це діапазон усіх доступних записів, незалежно від поточних фільтрів черги. Дати показані в Europe/Kyiv. Автоматичне оновлення періоду кешується на 30 секунд; ручний Refresh та очищення запитують його повторно.

## Export tasks: архів перед видаленням

1. Відкрий Export tasks.
2. Вибери From date і Through date. Обидва дні включаються; межі рахуються в Europe/Kyiv з урахуванням переходу на літній/зимовий час. Відбір іде за датою створення задачі, а не за завершенням.
3. Натисни Download ZIP archive. Пошук, користувач, статус і джерело в основній черзі не обмежують цей експорт — лише явно вибрані дати та твої права на хости.
4. Переконайся, що ZIP завантажився й відкривається, перш ніж видаляти історію.

Структура архіву:

```text
manifest.json
README.txt
2026-10-24/
  jobs/<job-id>/hosts/<endpoint-id>/<task-id>/
    task.json
    result.log
    input.json  # лише для інтерактивного superadmin
```

Task.json містить метадані, статус, причину запуску, timestamps, outcome/exit code, якщо вони існують. Result.log містить збережений результат. Input.json — параметри/скрипт задачі. Відомі чутливі поля й текстові шаблони маскуються в експорті; це не гарантує виявлення всіх секретів, тому перевір архів перед передаванням іншим. Назви папок формуються з безпечних ID, а не з недовірених імен хостів.

Неадміністратор експортує лише дозволені хости, без input.json. API keys не можуть експортувати або видаляти історію через ці endpoints. Експорт аудитується. ZIP не містить інсталяторів, зовнішніх файлів, звітів або повного backup сервера. Це архів для читання, а не пакет автоматичного відновлення чи запуску задач. Активні задачі можна експортувати в їх поточному стані; результат після цього може змінитися.

Ліміт одного архіву — 10 000 задач і 100 MiB сумарного вихідного тексту до стиснення. Якщо діапазон більший, сервер повертає помилку й пропонує менші діапазони; прихованого обрізання немає. Архів готується у тимчасовому файлі, великі архіви не тримаються повністю в RAM.

## Clean History: довільний вік у днях

Очищення доступне лише інтерактивному superadmin.

1. Натисни Clean History та введи цілу кількість днів від 1 до 3650.
2. Preview cleanup покаже кількість придатних записів і точну дату/час межі. Вік — кількість 24-годинних днів від поточного часу сервера, а не номер календарного місяця.
3. Export before deleting відкриє експорт від найстарішого запису до календарного дня межі очищення. Останній день експорту включається повністю, тому архів може містити й додаткові записи цього дня.
4. Після перевірки ZIP знову відкрий Clean History, переглянь preview й підтвердь Delete eligible records.

Видаляються лише завершені Success/Error/Cancelled, створені й завершені до межі; legacy completed-записи без finished_at також підтримуються. Pending, PickedUp, Running, SoftwareQueued, невідомі результати й записи відкритих Scheduler runs захищені. Якщо в запуску є активна задача, його завершені задачі також зберігаються. Активні/очікувані Software steps не очищаються.

Очищення глобальне для всіх хостів і не залежить від фільтрів черги. Воно не видаляє Aggregated Reports, Scheduler Run history, audit, визначення розкладів або файли інсталяторів. Пошукові індекси видалених задач прибираються разом із записами. Обробка йде пакетами до 5000 задач, інтерфейс показує прогрес. Якщо запит перерветься, уже завершені пакети залишаються видаленими; зроби новий preview для продовження. Preview діє 30 хвилин, дата межі під час пакетного очищення фіксована.
