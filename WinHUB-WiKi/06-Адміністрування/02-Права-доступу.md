# Права доступу

## Базові права

- `View` — перегляд вузлів, груп, queue і reports;
- `Change` — запуск задач, редагування, scheduler, triggers, software;
- `Delete` — destructive cleanup/delete/block operations.

## Детальні права

Основні granular permissions: `view_hosts`, `view_groups`, `view_queue`, `view_reports`, `view_sensitive_reports`, `run_tasks`, `run_own_draft_templates`, `manage_hosts`, `manage_groups`, `manage_templates`, `manage_software`, `manage_scheduler`, `manage_triggers`, `send_reports`.

`run_own_draft_templates` — явне високоризикове право для інтерактивної розробки шаблонів. Воно не входить у module-wide grant або legacy `Change`, не працює через API key і потребує також `manage_templates` та `run_tasks`. Користувач може вручну запустити тільки власну action/metric-чернетку; AI-чернетка має мати успішну валідацію, прив'язану до поточного коду. Scheduler/Trigger і спільний запуск усе одно потребують superadmin approval. Обмежуйте це право canary-групами через group permissions.

## Рекомендації

- відділяйте `view_sensitive_reports`;
- не поєднуйте template creation або `run_own_draft_templates` із необмеженим production rollout без review;
- group access має обмежувати видимість endpoint-вузлів;
- `Delete` і `cleanup_tasks` надавайте мінімальній кількості користувачів;
- перевіряйте effective access тестовим account.
