# Користувачі та ролі

## Створення користувача

1. Відкрийте `Admin → Users`.
2. Створіть іменний account.
3. Увімкніть лише потрібні modules.
4. Призначте group access.
5. Надайте granular permissions.
6. Передайте initial credentials через захищений канал.
7. Перевірте MFA і перший вхід.

## Життєвий цикл

- регулярно переглядайте active users;
- disable account до завершення розслідування/звільнення;
- reset credentials лише після перевірки identity;
- видалення виконуйте з урахуванням audit attribution;
- зберігайте щонайменше одного активного адміністратора.

Shared accounts знижують якість аудиту й не рекомендуються.
# Зміна власного пароля

У повному інтерфейсі біля Sign Out натисніть значок користувача **My account**.
На телефоні відкрийте меню → **My account · Change password**.
На сторінці `/account` введіть поточний пароль, новий та повторіть новий.
Вимоги: 12–128 символів, великі й малі літери, цифра та спеціальний символ,
без пробілів; новий пароль має відрізнятися від поточного. Перевірка виконується
сервером. Поля паролів не записуються в аудит.

Після зміни поточний браузер залишається авторизованим, інші браузерні сесії
стають недійсними при наступному запиті. Інші remembered sessions відкликаються;
поточна remembered session зберігає свій строк дії. Посилання **Continue**
оновлює сторінку та CSRF-токен. Невикористані коди відновлення пароля видаляються.
API keys не дають права викликати цей сценарій. Ліміт — 5 спроб на хвилину
за правилами серверного rate limiter. Права адміністратора для зміни власного
пароля не потрібні. Для оновлення наявного сервера потрібна міграція `20261120_01`.
