# Політика погодження Software

Скрипти Install/Update/Uninstall і Detection зберігаються до 25 000 символів кожен (включно з Unicode).
Розмір понад ліміт повертає помилку без збереження змін; мовчазного обрізання немає.
Старі скрипти, збережені з обрізанням на 12 000 символах, потрібно повторно вставити
з оригіналу після оновлення сервера та погодити відповідно до обраної політики.

Типово кожний застосунок використовує **Review every change**. Зміна коду,
пакета, версії або інших полів рецепта потребує нового погодження суперадміна.

Суперадмін із доступом до Software відкриває **Approval policy** на картці.
Спочатку потрібно переглянути й погодити поточну версію через **Review and approve**.
Потім увімкнути **Allow selected editors to publish changes without approval**,
вибрати користувачів із правом `manage_software` та натиснути **Save policy**.
На картці з'явиться блакитна позначка **Trusted edits**. Підказка містить автора
дозволу й редакторів (для менеджерів). Суперадміни також можуть зберігати зміни
такого застосунку без нового ручного погодження.

Окремі позначки картки: політика **Trusted edits** (блакитна) або **Review every
change** (жовта); поточний рецепт **Approved** (зелена) або **Approval required**
(жовта); пакет **Ready** (зелена), **Preparing / Preparation required** (жовта)
або **Preparation failed** (червона). Дозвіл довірених правок не означає, що
файл уже завантажений або поточна ревізія погоджена.

Дозвіл стосується тільки цього застосунку. При створенні нового застосунку
політика типово `review`; звичайні поля форми не можуть встановити делегування.
Невибраний редактор може зберегти зміни відповідно до свого доступу до Software,
але така версія потребуватиме погодження. Подальше звичайне збереження довіреним
редактором не знімає цю вимогу. Видалення права `manage_software` або блокування
користувача припиняє можливість редагувати через API.

Вимкнення **Trusted edits** скидає погодження поточної версії: для наступного
розгортання потрібний **Review and approve**. Уже запущені deployment snapshots
не змінюються. Підготовка файлів, SHA-256, підписи задач, права на цільові хости,
перевірка Workspace templates і ліміти виконання залишаються обов'язковими.
Agent Bootstrap та бібліотека Installers не використовують цю політику.

Політика зберігається у серверному JSON запису SoftwarePackage, без нової колонки
БД. Операції серіалізуються catalogue lock; policy revision запобігає збереженню
застарілого рішення. В аудиті є зміна політики, редактори й hash ревізії рецепта;
збереження довіреної правки містить ім'я автора. Це не окремий архів повних diff
скриптів. Розгорнуті snapshots продовжують зберігати виконану версію.
