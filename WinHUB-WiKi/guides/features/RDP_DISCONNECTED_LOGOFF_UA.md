# Завершення відключених RDP-сесій

Імпортуйте [rdp_disconnected_logoff_pack.json](../../../WinHUB/deploy/import_templates/rdp_disconnected_logoff/rdp_disconnected_logoff_pack.json), перевірте й погодьте шаблон `RDP — Log off disconnected users`.

Пакет також містить пов'язаний HTML-шаблон `RDP Session Report`: погодьте обидва шаблони. Звіт показує таблицю підсумків по серверах та окремі таблиці активних користувачів, завершених сесій, кандидатів Audit, помилок і пропущених користувацьких сесій. Службові записи без користувача приховано, крім помилок. Часткові результати невдалих задач також включено. У таблицях відображаються стан і протокол; старі результати без протоколу показують відповідну позначку.

Якщо попередній пакет уже імпортовано, повторний імпорт оновлює шаблон дії й додає шаблон звіту; погодження потрібно повторити. Створіть **нову задачу** з оновленого шаблону та перевірте, що вибрано звіт `RDP Session Report`. Раніше створені задачі й незмінні snapshots звітів автоматично не змінюються. Для таблиць у переглядачі відкрийте **Preview**. Сам JSON залишається машинним результатом агента.

- `Mode=Audit` показує відключені RDP-сесії, які можна завершити; нічого не змінює.
- `Mode=LogoffDisconnected` завершує всі знайдені відключені RDP-сесії з користувачем на локальному сервері, включно із сесіями адміністраторів. Мінімального часу відключення немає.

Завершення сесії закриває її програми й може втратити незбережені дані. Воно не видаляє Windows-профіль або збережені Telegram-сесії. Скрипт працює з правами адміністратора / LocalSystem, не використовує WinRM і не виконує перезавантаження. Спочатку запустіть Audit, потім створіть нову задачу LogoffDisconnected на потрібних серверах. За великої кількості сесій збільште штатний timeout задачі: кожен WTS logoff синхронний.

Через Windows WTS API відбираються `WTSDisconnected` (4), session ID > 0 та непорожнє ім'я користувача, якщо сесія не є консольною. Протокол більше не є умовою відбору: у наданому результаті WIN-TER412 відключені користувацькі сесії повернули `protocol=0`, тому попередній фільтр `protocol=2` помилково пропускав їх. Консоль визначається окремо через `WTSGetActiveConsoleSessionId` та назву станції `Console`; це перевіряється повторно перед виходом. Завершуються відключені неконсольні користувацькі сесії незалежно від протоколу. Поля `station` та `is_console` зберігаються для діагностики. Консоль, session 0, listener і активні сесії пропускаються. Активний користувач без руху миші також залишається працювати: idle не означає disconnected. Розбір локалізованого тексту `quser` не використовується.

Перед кожним виходом повторно перевіряються стан, виключення консолі та ім'я/домен. Якщо користувач уже підключився, сесія пропускається. Між останньою перевіркою і WTSLogoffSession залишається коротке вікно гонки: API не має атомарної операції «вийти лише якщо досі disconnected». Запускайте задачу у погоджений період очищення. Якщо користувач перепідключиться саме в цей момент, вихід усе ще можливий. Нові відключення після початкового знімка обробляються наступним запуском.

JSON-звіт у результаті задачі містить список активних користувачів (`status=Active`, лічильник `active`), завершених сесій (`status=LoggedOff`), пропущених сесій і помилок. Стан активних сесій фіксується під час їх перевірки, а не є постійним моніторингом. JSON-результат містить `logged_off`, `would_logoff`, `failed` та окремий запис для кожної перевіреної сесії. Помилки читання/виходу не маскуються як успіх; інші сесії продовжують оброблятися. У звіті є імена користувачів — застосовуйте штатні права доступу WinHUB. Шаблон не налаштовує автоматичний розклад.

Контракт API: [WTS_INFO_CLASS](https://learn.microsoft.com/en-us/windows/win32/api/wtsapi32/ne-wtsapi32-wts_info_class), [WTSLogoffSession](https://learn.microsoft.com/en-us/windows/win32/api/wtsapi32/nf-wtsapi32-wtslogoffsession).

Запускайте шаблон на хостах із установленим Windows-агентом WinHUB: агент виконує скрипт локально на кожному вибраному сервері. Для регулярного очищення створіть завдання Scheduler із цим шаблоном, режимом `LogoffDisconnected` і потрібною групою RDP-серверів. Поріг idle не застосовується: причина завершення — стан disconnected.

Назва й увесь текст звіту — англійською: **RDP Session Report**. Після оновлення пакета повторно імпортуйте та погодьте обидва шаблони, потім створіть нову задачу Audit. Старі результати не перераховуються.
