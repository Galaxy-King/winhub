# Zabbix Agent 2 — налаштування через WinHUB

Для ручного імпорту: [zabbix_agent2_winhub_pack.json](../../../WinHUB/deploy/import_templates/zabbix_agent2/zabbix_agent2_winhub_pack.json).

Пакет містить один непогоджений action-шаблон **Zabbix Agent 2 — Configure with PSK**. Ключ вводиться вручну в `PSKSecretValue`, без Template Secrets. Порожній default ключа збережено. Значення не повертається в результаті; назва поля підтримує наявне маскування sensitive-змінних WinHUB. Не записуйте робочі ключі до шаблону або JSON-пакета.

Шаблон виконує Windows-агент WinHUB з адміністративними правами. Він налаштовує вже встановлений Zabbix Agent 2, не встановлює його, не змінює firewall і не налаштовує Zabbix Server. Потрібна підтримка перевірки `zabbix_agent2.exe -T`.

## Повторне встановлення для тесту

1. Перед видаленням Zabbix збережіть чинний PSK із `psk.key` у захищеному місці: у наданому конфігу є лише шлях, самого ключа немає. Збережіть також конфіг. WinHUB-агент залиште встановленим.
2. Видаліть і встановіть Zabbix Agent 2 заново зі стандартним конфігом як службу. Самого WinHUB-агента для цього шаблону недостатньо.
3. Імпортуйте пакет, перегляньте та погодьте шаблон. Попередній **Zabbix Agent 2 — Configure** без поля PSK видаліть із бібліотеки вручну, якщо імпортували його раніше: новий пакет не видаляє старі записи.
4. Створіть нову задачу після повторного імпорту: вже відкриту форму або стару задачу не використовуйте, бо вони можуть містити попередній перелік полів. Виберіть один тестовий хост і заповніть поля за таблицею. Спочатку запустіть Preview, після перевірки — Apply.

## Поля для наданого конфігу

| Поле | Значення |
| --- | --- |
| Operation | `Preview`, потім `Apply` |
| CheckMode | `Both` |
| PassiveServers | `192.168.38.254` |
| ActiveServers | `192.168.36.254` |
| HostnameMode | `Custom` |
| CustomHostname | `192.168.38.9` — лише для хоста з прикладу |
| MetadataMode | `List` |
| MetadataValue | `Windows_2P` |
| PSKIdentity | `PTERMINALSIDENTITYK` |
| PSKSecretValue | Вміст вашого `psk.key`, не шлях до нього |
| AgentDirectory | `C:\Program Files\Zabbix Agent 2` |
| ServiceName | `Zabbix Agent 2` — звірте з установленою службою |
| PSKFile | `C:\Program Files\Zabbix Agent 2\psk.key` |

На інших хостах задавайте їхній hostname, який збігається з технічним ім’ям у Zabbix; або використовуйте `ComputerName`, якщо в Zabbix потрібне ім’я Windows. IP із прикладу не є універсальним default.

PSK — 32–512 hex-символів парної довжини, без пробілів/переносів. Введіть його також для Preview. Такий самий ключ та identity мають бути налаштовані в Zabbix для хоста або відповідного сценарію автореєстрації. Для групового запуску введений ключ та CustomHostname спільні для всіх цілей; різні значення задавайте окремими задачами.

Форма містить 13 основних полів, усі назви та підказки англійською. TLS завжди PSK. Поля LogFile, ControlSocket та Include вилучені; їхні наявні значення в конфігу зберігаються без змін.

## Метадані та порядок полів

Список `MetadataValue.options` починається з `Windows_2P`. Нові значення додавайте в **Variable Field Schema**, наприклад `"options": ["Windows_2P", "Windows_Office"]`. Після редагування повторно погодьте шаблон. Відповідні правила автореєстрації та групи налаштовуються в Zabbix; зміна метаданих сама по собі не гарантує перенесення наявного хоста до іншої групи.

`MetadataMode=Disabled` прибирає HostMetadata та HostMetadataItem; `List` використовує список. Для автореєстрації потрібний активний зв’язок.

Числовий атрибут `order` у специфікації поля задає порядок: менші значення вище. Він підтримується основною формою, швидким запуском, Scheduler і мобільною формою. Поля без числового order зберігають попередню взаємну послідовність і йдуть після впорядкованих. Для відображення цього порядку на встановленому сервері потрібні оновлені JS-файли WinHUB; лише імпорт JSON у старий сервер не змінює алфавітного порядку його форм.

## Застосування й обмеження

Preview перевіряє параметри, службу та шляхи, але не записує файли й не запускає повну перевірку конфігурації. Apply створює backup, обмежує ACL PSK/backup/candidate до SYSTEM, Administrators та облікового запису служби, перевіряє кандидат через `-T`, перезапускає службу та перевіряє її стан. Після помилки заміни конфігу виконується спроба відкату. Працездатність зв’язку із Zabbix перевіряйте окремо.

- Підтримується `zabbix_agent2.conf` у AgentDirectory; інший конфіг у команді служби відхиляється.
- Наявний PSK-файл з іншим ключем не перезаписується: для ротації вкажіть новий PSKFile.
- LogFile, ControlSocket та Include не налаштовуються через шаблон. Поля для item-based hostname/metadata, буферів, debug, certificate TLS, UserParameter та інших розширених опцій вилучені зі схеми та placeholders скрипта; наявні налаштування в конфігу зберігаються. HostnameItem/HostMetadataItem прибираються узгоджено з вибраними режимами hostname/metadata.
- Include-файли не переписуються; перевіряйте дублікати й порядок AllowKey/DenyKey. `-T` перевіряє сумісність із установленою версією.
- Параметри використовують чинну raw substitution WinHUB і призначені для довірених адміністраторів. Окремий рядок `'@` у введених даних може завершити PowerShell here-string; runtime-валідація не усуває цей ризик.
- Сирі помилки агента не повертаються, щоб не розкрити ключі.

Джерела: `WinHUB/deploy/import_templates/zabbix_agent2/`; перегенерація — `python build_pack.py`. Перевірки: структура/схема пакета, PowerShell parser і Preview на фікстурі. Живий імпорт, Apply на встановленому Zabbix та зв’язок із сервером у цій задачі не виконувалися.

Для імпорту вибирайте лише `zabbix_agent2_winhub_pack.json`. `template_definition.json` — службове джерело без скрипта, не імпортний пакет. Якщо в Code з’явився JSON із `__variable_schema`, повторно імпортуйте повний пакет, погодьте шаблон і створіть нову задачу. Стару задачу не повторюйте.

## Діагностика відмови до застосування

Шаблон повертає англомовні `error_code`, `field`, `check`, `message` без сирих exception, виводу агента або значень введених полів.

- `PSK_FILE_CONFLICT`: PSKFile містить інший ключ; для ротації задайте новий шлях. Не видаляйте чинний ключ для обходу перевірки.
- `INVALID_PSK_FORMAT`: потрібні 32–512 hex-символів парної довжини без пробілів і переносів.
- `AGENT_EXECUTABLE_MISSING` / `AGENT_CONFIG_MISSING`: перевірте встановлення й AgentDirectory.
- `SERVICE_NOT_FOUND` / `SERVICE_EXECUTABLE_MISMATCH` / `SERVICE_CONFIG_MISMATCH`: звірте службу та шляхи.
- `REQUIRED_FIELD`: заповніть поле з `field`.
- `UNEXPECTED_ERROR`: перевірте права й операцію з `check`; сирий текст помилки прихований.

`stage=validation, rollback=NotNeeded` означає відмову до запису файлів. Старе загальне повідомлення не визначає причину. Повторно імпортуйте повний пакет, погодьте та створіть нову задачу Preview, щоб отримати точну діагностику.
