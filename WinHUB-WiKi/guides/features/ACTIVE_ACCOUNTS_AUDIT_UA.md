# Аудит активних локальних облікових записів

Пакет для ручного імпорту: [active_accounts_pack.json](../../../WinHUB/deploy/import_templates/active_accounts/active_accounts_pack.json).
Він містить action PowerShell для Windows та пов'язаний зведений report.

1. У бібліотеці шаблонів імпортуйте JSON через наявний механізм імпорту.
2. Перегляньте й погодьте шаблони за правилами вашого WinHUB.
3. Створіть одне завдання «Аудит активних локальних облікових записів» на потрібну групу Windows-хостів.
4. Після завершення збору відкрийте зведений звіт цього завдання.

Скрипт лише читає локальну SAM через `Win32_UserAccount`, фільтр `LocalAccount=True`.
Активна обліковка має `Disabled=False` і `Lockout=False`; поточний вхід чи наявність сеансу не потрібні.
Вбудовані та службові акаунти включаються на тих самих умовах. Доменні обліковки,
права RDP, строк дії облікового запису та можливість фактичного входу не перевіряються.

Звіт показує кількість успішно перевірених хостів, суму активних обліковок на них
та кількість унікальних логінів без урахування регістру й імені хоста.
Наприклад, `Olena` на одному терміналі та `olena` на іншому — дві обліковки, один унікальний логін.
Це оцінка користувачів за логінами: однаковий логін різних людей буде об'єднано,
а різні логіни однієї людини — пораховано окремо.

Помилка запиту чи невідомий стан акаунта завершує аудит хоста з помилкою.
Такий хост не рахується як хост із нулем користувачів. Помилки та відсутні дані
позначають підсумок як неповний. Офлайн-хости потрібно також звірити зі складом
цільової групи й станом завдання: звіт бачить лише результати, передані WinHUB.
Збір відбувається в різний час на різних хостах, стан блокування може змінюватися.

Вихідні файли та відтворювана збірка JSON: [каталог пакета](../../../WinHUB/deploy/import_templates/active_accounts/).
Після зміни `.ps1` або `.jinja` запустіть `python build_pack.py` з цього каталогу.
