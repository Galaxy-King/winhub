# Структура репозиторію

Усі шляхи в таблиці відраховуються від кореня Git checkout.

| Шлях | Призначення |
| --- | --- |
| `WinHUB/` | Серверна частина Python |
| `WinHUB/core/` | Auth, security, database, Agent Gateway, admin, SDK |
| `WinHUB/modules/` | Infrastructure, HistoryAudit, Newsletter |
| `WinHUB/templates/`, `WinHUB/static/` | Вебінтерфейс |
| `WinHUB/migrations/` | Alembic migrations |
| `WinHUB/deploy/debian/` | Install, update, backup, restore, systemd і Nginx |
| `WinHUB/deploy/import_templates/` | Готові task/report packs |
| `WinHUB/tests/` | Серверні regression tests |
| `WinHUBAgentWindows/` | Windows agent; проєкт `WinHUBAgentWindows.csproj` |
| `WinHUBLinuxAgent/` | Linux agent і спільний Unix Worker |
| `WinHUBMacAgent/` | macOS agent; власні `docs/` і `tests/` |
| `WinHUB-WiKi/` | Документація всіх компонентів |
| `WinHUB-WiKi/guides/` | Докладні посібники за темами |
| `.github/workflows/` | Перевірки всіх компонентів |

Windows project зберігає `AssemblyName=WinHUBAgent`, назву служби та формат update-пакетів, тому нова назва каталогу не вимагає перевстановлення агентів. macOS підключає `../WinHUBLinuxAgent/Worker.cs`; ці два каталоги потрібно завантажувати разом.

`WinHUBLinuxAgent/Security/*.cs` містить спільні перевірки pin, task envelope, atomic storage, bounded I/O та archive extraction. Windows/macOS підключають ці файли через `Compile Link`, щоб не розходилися security-перевірки. Тому для складання Windows також потрібні ці вихідні файли Linux-компонента. Спільні зміни перевіряти для всіх трьох проєктів; поточний обсяг і release gates — у [посібнику strict pin](../guides/agents/PRODUCTION_PIN_AGENTS_UA.md).

Після встановлення вміст `WinHUB/` розміщується безпосередньо в `/opt/winhub`. Агенти, Wiki та Git metadata туди не копіюються. Налаштування й дані залишаються у `/etc/winhub` та `/var/lib/winhub`.

Кореневий `.gitignore` дозволяє лише компоненти проєкту. Локальні backups, archives, інші checkout-и, caches, releases і runtime-секрети виключені. Історія Git спільна для всіх компонентів; робочий каталог сервера також можна використовувати для Git-команд.
