# AI-редактор: архітектура та межі довіри

## Рішення

Модель генерує **дані чернетки**, а не виконує інструкції. Приватна сутність `AiTemplateDraft` відокремлена від `TaskTemplate` та `AgentTask`. Контракт `winhub-template-v1` задається в `WinHUB/core/ai_template_contract.py`; Flask не імпортує worker перевірки. Інтерфейс використовує наявний CodeMirror, Open WebUI provider та workflow затвердження шаблонів.

```text
Промпт + явно вибраний reference code
  → private draft / черга
  → Open WebUI: лише text completion, tools вимкнені
  → строгий JSON-контракт + ліміти
  → Unix socket → окремий validator UID
  → diagnostics + hash → перегляд тексту/diff
  → Apply у редактор АБО Save нових непогоджених templates
  → окреме затвердження → окремий явний запуск на хостах
```

## Компоненти

| Компонент | Відповідальність |
| --- | --- |
| `core/ai_template_contract.py` | Строгі поля, мови, byte limits, SHA-256, синтетичний report context, промпт |
| `core/ai_templates.py` | Claim через row lock, recheck автора/provider, completion, validation, cancellation fencing, retention |
| `modules/Infrastructure/ai_editor.py` | Owner-only API, explicit permissions, rate limits, статична перевірка змін, idempotent save |
| `core/code_validator_client.py` | Обмежений Unix socket protocol, перевірка hash, без subprocess fallback |
| `core/code_validator.py` | Довірений worker: PowerShell ParseFile, Bash `-n`, optional linters, restricted Jinja render |
| `core/validate_powershell.ps1` | Фіксований wrapper; submitted code ніколи не викликається |
| `static/js/ai_template_editor.js` | Private history, polling, text-only output, diff, explicit apply/save |
| `deploy/debian/winhub-code-validator*` | UID/OS isolation, no network/secrets, ресурсні ліміти |

## API та стани

Префікс: `/api/infrastructure/ai-editor`.

| Шлях | Дія |
| --- | --- |
| `GET /drafts` | 30 останніх приватних записів автора |
| `POST /drafts` | Створення Queued з prompt/language/include_report/опційним source_code |
| `GET /drafts/<id>` | Власна чернетка з текстом і діагностикою |
| `DELETE /drafts/<id>` | Cancelled; історія не видаляється одразу |
| `POST /drafts/<id>/validate` | Повторна перевірка незмінного збереженого bundle |
| `POST /check` | Новий bundle із поточного редактора, без AI/model request |
| `POST /drafts/<id>/save` | Нові непогоджені templates, ідемпотентно |

Generation: `Queued → Running → Ready / Error`; повторна перевірка: `Ready → Validating → Ready`. **Ready не означає безпечний чи валідний код**: окремо потрібні `validation.ok == true` та актуальний `code_hash`. Cancelled не перезаписується пізньою відповіддю. Running/Validating старше 15 хвилин переходять у Error без прихованого повторного запиту. Перевірка не виконує скрипт на хості.

Чернетки мають encrypted-at-rest prompt/source/result/validation через наявний `EncryptedText`; метадані, owner, timestamps і saved IDs відкриті для роботи черги. API не повертає source_code або provider key. Retention 30 днів виконується тим самим scheduler. Не робіть вивантаження таблиці в audit logs.

## Обмеження першої версії та причини

- AI-code не використовує legacy `{{variables}}`/secret substitution: параметри зараз вставляються в рядок скрипта, а не передаються типізованим data channel. Згенеровані скрипти мають configuration constants. Новий input binding — окрема зміна протоколу сервера й агентів.
- Marker `__ai_generated` зберігається при редагуванні/клонуванні. Непогоджені AI actions не користуються `own_runnable`-винятком навіть для адміністратора. Зміни в шаблоні інвалідовують approval hash штатним механізмом. Ручне копіювання коду в звичайний немаркований шаблон адміністратором не є механізмом відстеження provenance й не може бути заборонене цією ознакою.
- Validator only: no same-user fallback, no запуск submitted script, no dynamic rules/installers. Missing parser блокує Apply/Save; missing optional lint повертає warning. Resource limits діють на worker і його дочірні процеси.
- Повний AI HTTP body обмежений до JSON parsing; output додатково перевіряється контрактом. Network timeout і monotonic checks не є окремим killable worker deadline для slow-drip peer — AI scheduler досі працює в application process.
- Модель і parser не доводять поведінку скрипта. Windows PowerShell 5.1/Windows APIs і native macOS перевіряються на відповідній ОС окремим canary. Немає automatic run-on-save.
- Передається лише явно вибраний код/промпт, не live outputs/секрети/БД. Це не RAG і не універсальний автономний агент. Не підключайте виконувані Open WebUI Tools для обходу окремої служби.
- Новий validator не усуває старі F01–F11 в [аудиті ізоляції](../guides/security/SECURITY_RULES_AND_ISOLATION_UA.md); там зазначені частково закриті місця й потрібні production checks.

## Regression та розгортання

`WinHUB/tests/test_ai_template_editor.py` перевіряє приватність, explicit/non-API permissions, masking, malformed/oversized outputs, quota, revocation, cancel fencing, draft-only generation, immutable hash, idempotent unapproved save, approval gate, no legacy binding, no tool calls, native parser non-execution. Mocked model/validator перевіряє application contract, не фактичну конфігурацію приватного Open WebUI.

SQLite regression застосовує міграції до `20260904_01`. Production PostgreSQL install/update/restore й sandbox escape probes мають перевірятися на disposable Debian VM. Install/update/restore підключають окремі units; healthcheck перевіряє реальний socket синтетичним Jinja fixture без виклику ШІ. Server release allowlist уже включає `core/`, `modules/`, `static/`, `migrations/`, `deploy/`; не потрібно копіювати agents/tests/Wiki в installed app.

Практичний сценарій, залежності та діагностика: [AI-редактор](../guides/features/AI_TEMPLATE_EDITOR_UA.md).
