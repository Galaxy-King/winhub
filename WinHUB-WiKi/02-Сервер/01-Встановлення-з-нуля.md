# Встановлення сервера з нуля

## Результат

Після завершення працюють PostgreSQL, Nginx, WinHUB і Report Renderer. Скрипт сам генерує незалежні криптографічні секрети, створює БД, застосовує міграції, запускає служби та виконує healthcheck.

## Перед початком

Потрібні:

- чистий Debian 12;
- root або sudo;
- DNS-ім’я чи статична IPv4-адреса сервера;
- доступ до Git-репозиторію;
- окреме зашифроване сховище для recovery bundle.

Не готуйте паролі вручну. Інсталятор створить їх через системний CSPRNG.

## 1. Завантажте проєкт із Git

Варіант із checkout у домашньому каталозі:

```bash
sudo apt update
sudo apt install -y git ca-certificates
git clone <WINHUB_GIT_URL> ~/winhub
cd ~/winhub
```

Інсталятор скопіює робочий checkout до `/opt/winhub`. Якщо deploy key уже налаштований для root, репозиторій можна клонувати безпосередньо в `/opt/winhub`.

## 2. Запустіть інсталятор

```bash
sudo bash deploy/debian/install_debian.sh
```

Нову інсталяцію потрібно запускати в інтерактивному SSH або локальному terminal-сеансі.

## 3. Вкажіть адресу сервера

Скрипт запропонує знайдену IPv4-адресу. Введіть DNS-ім’я або адресу, яку використовуватимуть браузери й агенти.

```text
Public DNS name or IPv4 address [192.0.2.10]: winhub.example.net
```

Це значення потрапить у SAN автоматично створеного TLS-сертифіката та `AGENT_PUBLIC_BASE_URL`.

## 4. Підтвердьте генерацію секретів

Інсталятор створює окремі випадкові значення для:

- Flask sessions;
- PostgreSQL;
- enrollment агентів;
- підпису задач.

Значення не беруться з WiKi, Git або шаблонного env. Після повідомлення натисніть Enter. Секрети будуть додані до одноразового recovery bundle наприкінці.

## 5. Дочекайтеся автоматичного налаштування

Скрипт виконає:

- встановлення системних пакетів і Python virtual environment;
- створення користувачів `winhub` і `winhub-renderer`;
- створення PostgreSQL role/database;
- генерацію TLS certificate/private key;
- конфігурацію systemd і Nginx;
- Alembic migrations;
- запуск сервісів;
- створення першого адміністратора;
- healthcheck backend і renderer.

## 6. Збережіть recovery bundle

Після успішного healthcheck скрипт створить одноразовий архів у `/run` і покаже шлях та SHA-256.

Архів містить:

- перший admin password і TOTP seed;
- `winhub.env`;
- TLS certificate і private key;
- `master_key.enc`;
- `sys_secret.enc`;
- контрольні суми.

Скопіюйте архів на довірений комп’ютер або зашифроване off-host сховище. Перевірте SHA-256. Лише після цього введіть:

```text
SAVED
```

Після підтвердження інсталятор видаляє одноразовий архів і дубль першого admin recovery із сервера. На сервері залишаються лише ключі та секрети, необхідні для роботи.

Якщо SSH-сеанс перервався до `SAVED`, тимчасовий архів у `/run` видаляється. Повторно запустіть installer: наявні runtime secrets не ротуються, а recovery bundle буде відтворено з потрібних server files та initial admin recovery.

Recovery bundle заборонено завантажувати в Git, Confluence, ticket, email, chat або незашифроване cloud-сховище.

## 7. Перевірте результат

```bash
sudo systemctl status winhub --no-pager
sudo systemctl status winhub-renderer.socket --no-pager
sudo nginx -t
sudo /opt/winhub/deploy/debian/healthcheck_winhub.sh
```

Відкрийте:

```text
https://<WINHUB_SERVER>
```

Для автоматично створеного self-signed certificate спочатку розгорніть довіру до внутрішнього CA або замініть сертифікат на trusted certificate. Не вимикайте TLS verification на агентах.

## 8. Перші обов’язкові дії

1. Увійдіть даними з recovery bundle.
2. Змініть admin password.
3. Залиште MFA увімкненою.
4. Створіть і перевірте encrypted off-host backup.
5. Встановіть один тестовий агент і підтвердьте його в Review Center.
6. Після rollout закрийте enrollment window або налаштуйте allowlist.
