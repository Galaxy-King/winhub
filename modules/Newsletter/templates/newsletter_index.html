Newsletter Guide

How to configure direct campaigns and inbound relay routes.

What The Module Does

Newsletter sends encrypted announcements to selected recipients. You can send a campaign manually from the web interface or configure an inbound relay mailbox. Inbound relay reads encrypted emails from a dedicated mailbox and forwards them to predefined local lists and LDAP / FreeIPA groups.

Quick Setup: Inbound Relay

  1. Create a Mail Profile for the mailbox that will receive relay emails. Fill in SMTP, IMAP, and the GPG passphrase if the private key is protected.
  2. Import the private GPG key for that mailbox into the server keyring. The message sent to this mailbox must be encrypted for this key.
  3. Create local mailing lists or configure an LDAP / FreeIPA profile.
  4. Open Settings, go to Inbound Relay, create a route, and select which mail profile to read from and which profile to send from.
  5. Add allowed senders. Only these users can trigger the relay.
  6. Select one or more local lists, LDAP groups, or both. Duplicated recipients are sent only once.
  7. Save the route and send an encrypted test email to the relay mailbox.

Mail Profiles

  • Email is the mailbox identity used by the profile.
  • SMTP settings are used to send outgoing emails.
  • IMAP settings are used to read incoming relay emails from the mailbox.
  • GPG Passphrase unlocks the private key for inbound decryption. It is stored encrypted and is never shown back in the UI.
  • Keyserver is used as a fallback when a recipient public key is missing locally.

Inbound Relay Route Fields

  • Route Name is a friendly name for this relay rule, for example IT Support Relay.
  • Read From Mail Profile is the mailbox where WinHUB checks incoming encrypted emails.
  • Send From Mail Profile is the mailbox used to send forwarded messages. Auto means use the same profile as reading.
  • Allowed Senders controls who may send emails to this relay mailbox.
  • Local Mailing Lists are manually managed recipient lists inside Newsletter.
  • LDAP Groups are external directory groups resolved through LDAP / FreeIPA.
  • Recipient Domain is appended only to local list entries without @. Example: spock plus @example.com becomes spock@example.com.
  • Recipient Keyserver overrides the send profile keyserver for this route.

Recipient List Types

  • Manual campaign lists are used when an operator sends a newsletter directly from the editor.
  • Local mailing lists are stored in WinHUB and can contain full emails or short usernames.
  • LDAP / FreeIPA groups are resolved dynamically. WinHUB reads group members and uses the configured email attribute, usually mail.
  • If the same email appears in several lists or groups, WinHUB sends only one message to that address.

LDAP / FreeIPA

LDAP is useful when recipients are already managed in a company directory. Instead of duplicating users manually in Newsletter, select LDAP groups in a relay route. WinHUB resolves the group members during sending and reads their email addresses from the configured attribute.

  • Use a read-only or low-privilege directory account whenever possible.
  • Use the test button to verify the bind credentials and check available groups.
  • If a group member has no email attribute, that member cannot receive the newsletter.

GPG Encryption And Keys

  • Inbound emails must be encrypted for the private key of the mailbox that WinHUB reads.
  • Outgoing messages are encrypted separately for each recipient public key.
  • If a public key is missing, WinHUB tries the route keyserver first, then the sending mail profile keyserver.
  • GPG signatures are optional. If a message decrypts successfully but the sender public key is missing for signature verification, the relay can still process the email.

Testing And Troubleshooting

  • Use Test Mail Profile to verify SMTP and IMAP access.
  • Use Test LDAP / Check Groups to verify LDAP credentials and group lookup.
  • Open Logs while sending a test message. Accepted messages move to the processed folder; rejected messages move to the failed folder.
  • If a recipient does not receive mail, check the public GPG key, recipient email address, SMTP result, and task log.

Що робить модуль

Newsletter надсилає зашифровані повідомлення вибраним отримувачам. Розсилку можна створити вручну у веб-інтерфейсі або налаштувати inbound relay. Inbound relay читає зашифровані листи з окремої поштової скриньки та пересилає їх у визначені локальні списки й LDAP / FreeIPA групи.

Швидке налаштування пересилки

  1. Створи Mail Profile для пошти, на яку надходитимуть листи для пересилки. Заповни SMTP, IMAP і GPG passphrase, якщо приватний ключ має парольну фразу.
  2. Імпортуй приватний GPG-ключ цієї пошти на сервер. Листи на цю пошту мають бути зашифровані саме для цього ключа.
  3. Створи локальні списки отримувачів або налаштуй LDAP / FreeIPA профіль.
  4. Відкрий Settings, перейди в Inbound Relay, створи route і вибери, з якої пошти читати та з якої пошти відправляти.
  5. Додай дозволених відправників. Тільки вони можуть запускати пересилку.
  6. Вибери один або кілька локальних списків, LDAP-груп або обидва типи одночасно. Дублікати отримувачів прибираються автоматично.
  7. Збережи route і надішли зашифрований тестовий лист на relay-пошту.

Mail Profiles

  • Email це адреса поштової скриньки профілю.
  • SMTP потрібен для відправлення листів.
  • IMAP потрібен для читання вхідних листів з relay-пошти.
  • GPG Passphrase розблоковує приватний ключ для розшифрування вхідного листа. Вона зберігається зашифровано і не показується назад у веб-інтерфейсі.
  • Keyserver використовується, якщо публічного ключа отримувача немає локально.

Поля Inbound Relay Route

  • Route Name це зрозуміла назва правила, наприклад IT Support Relay.
  • Read From Mail Profile це пошта, з якої WinHUB читає вхідні зашифровані листи.
  • Send From Mail Profile це пошта, з якої WinHUB відправляє переслані листи. Auto означає використовувати ту саму пошту, з якої читаємо.
  • Allowed Senders визначає, хто має право писати на relay-пошту для запуску пересилки.
  • Local Mailing Lists це списки отримувачів, які зберігаються в самому WinHUB.
  • LDAP Groups це групи з LDAP / FreeIPA, які WinHUB читає через LDAP-профіль.
  • Recipient Domain додається тільки до локальних записів без @. Наприклад spock плюс @example.com стане spock@example.com.
  • Recipient Keyserver перевизначає keyserver профілю відправника саме для цього route.

Типи списків отримувачів

  • Manual campaign lists використовуються, коли оператор вручну створює розсилку з редактора.
  • Local mailing lists зберігаються у WinHUB і можуть містити повні email-адреси або короткі ніки.
  • LDAP / FreeIPA groups беруться з корпоративного каталогу. WinHUB читає учасників групи й бере email з налаштованого атрибута, зазвичай mail.
  • Якщо одна адреса є в кількох списках або групах, WinHUB відправить їй лише один лист.

LDAP / FreeIPA

LDAP потрібен, якщо користувачі та групи вже ведуться в корпоративному каталозі. Тоді не потрібно дублювати всіх отримувачів вручну у Newsletter: достатньо вибрати LDAP-групи в route, а WinHUB під час відправлення сам отримає актуальні адреси.

  • Для LDAP бажано використовувати окремого користувача з мінімальними правами на читання.
  • Кнопка тесту перевіряє логін, пароль і пошук груп.
  • Якщо в користувача LDAP немає email-атрибута, він не зможе отримати лист.

GPG шифрування і ключі

  • Вхідний лист має бути зашифрований на приватний ключ тієї пошти, яку читає WinHUB.
  • Вихідні листи шифруються окремо під публічний ключ кожного отримувача.
  • Якщо публічного ключа немає локально, WinHUB спочатку пробує Recipient Keyserver route, потім keyserver профілю відправника.
  • GPG-підпис не є обов'язковим. Якщо лист успішно розшифровано, але public key відправника відсутній для перевірки підпису, пересилка може продовжитись.

Тестування і діагностика

  • Використовуй Test Mail Profile, щоб перевірити SMTP та IMAP доступ.
  • Використовуй Test LDAP / Check Groups, щоб перевірити LDAP-доступ і пошук груп.
  • Відкрий Logs під час тестової відправки. Успішні листи переходять у processed folder, помилкові у failed folder.
  • Якщо отримувач не отримав лист, перевір public GPG key, email-адресу, SMTP-результат і task log.
