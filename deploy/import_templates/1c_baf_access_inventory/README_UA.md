# WinHUB: інвентаризація 1С / BAF та доступу

Комплект призначений для ручного імпорту у WinHUB і запуску на групі Windows-хостів. Він нічого не встановлює та не змінює: лише збирає дані й формує один агрегований звіт.

## Файли

- `1c_baf_access_inventory_pack.json` — готовий пакет ручного імпорту (action + report).
- `1c_baf_access_inventory.ps1` — PowerShell action для Windows Agent.
- `1c_baf_access_inventory_report.jinja` — агрегований текстовий report.
- `build_pack.py` — повторно збирає JSON-пакет із двох вихідних файлів.

## Імпорт і запуск

1. Відкрийте `Infrastructure -> Deploy / Templates` або `Infrastructure -> Workspace` (залежно від версії інтерфейсу).
2. Натисніть `Import` / `Import templates`.
3. Виберіть `1c_baf_access_inventory_pack.json`.
4. Запустіть action `1C / BAF Access Inventory` на потрібній групі Windows-хостів.
5. Report `1C / BAF Access Inventory Report` уже прив'язаний до action у Post-Execution.

Поля Script Variables не потрібні. Типовий timeout одного endpoint — 5 хвилин.

## Що перевіряється

- програми в 64- і 32-бітних гілках Windows Uninstall;
- служби 1С / BAF;
- відомі каталоги та виконувані файли `1cv8`, `1cv7`, `ragent`, `ras`, `rmngr`, `1cestart` у `Program Files`;
- назви 1C:Enterprise, 1С:Підприємство, 1С:Предприятие, Business Automation Framework, BAF і BAS;
- усі локальні IPv4-адреси з діапазону `192.168.0.0/16`;
- члени локальних груп `Administrators` і `Remote Desktop Users` за їх SID, тому локалізація Windows не має значення;
- вкладені локальні та доменні групи до шести рівнів, якщо каталог доступний;
- стан кожного знайденого користувача: `Enabled/Disabled` і `LockedOut`.

Сервери зі встановленим ПЗ сортуються за IP числово, від меншого до більшого. Хости без адреси `192.168.*` ідуть після них. В самому кінці report завжди є окремий список `СЕРВЕРИ, ДЕ 1С / BAF НЕ ВСТАНОВЛЕНО`, також відсортований за IP.

## Що означає «має доступ»

До списку потрапляють лише конкретні облікові записи користувачів, для яких виконуються всі умови:

1. це локальний Windows-обліковий запис або доменний користувач, доступ якому надано через `Administrators` / `Remote Desktop Users` та вкладені групи;
2. стан облікового запису успішно перевірено;
3. `Enabled = true`;
4. `LockedOut/Blocked = false`.

Вимкнені, заблоковані та неперевірені облікові записи не виводяться в активному списку. Report показує лише їх кількість у рядку `Виключено`. Якщо сервер не може звернутися до домену, членів відповідної доменної групи не буде додано як активних, а причина з'явиться в `Попередження`.

Report навмисно короткий: на початку він підсумовує кількість серверів зі встановленим та невстановленим ПЗ, а для кожного IP показує лише факт `1С / BAF: ВСТАНОВЛЕНО` та список логінів активних користувачів без префікса хоста або домену (`HOST\user` відображається як `user`). Стани, джерела перевірки, групи доступу, версії, служби й шляхи до виконуваних файлів у картці сервера не виводяться. Технічні попередження згруповані за сервером в окремому блоці наприкінці report.

Локальна або доменна політика `Deny log on through Remote Desktop Services` може додатково заборонити вхід і цим автономним endpoint-аудитом не обчислюється.

Це не список внутрішніх користувачів інформаційної бази 1С/BAF. Внутрішні ролі та користувачі зберігаються в конкретній файловій або SQL-базі й потребують окремого підключення та облікових даних адміністратора 1С. Поточний шаблон навмисно не приймає і не збирає такі credentials.

## Права та сумісність

- WinHUB Agent бажано запускати як `LocalSystem` або локальний адміністратор.
- Скрипт сумісний із Windows PowerShell 5.1 і новішим PowerShell на Windows.
- Якщо частина WMI/CIM, реєстру, локальних груп або домену недоступна, task продовжує роботу, а причина потрапляє в `Попередження`.
- Сервер без 1С/BAF не вважається помилкою task — він потрапляє до фінального списку «не встановлено».
